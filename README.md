# Timeline Block

A React component that lays out a set of time periods as points on a rotating circular dial, with a slider of key events for the period currently selected. Picking a point turns the dial along the shortest arc, counts the period's start and end years up or down to their new values, and swaps the event slider below it. The repository holds the component plus a demo page that mounts it with six periods; demo content lives in `src/data/mock.ts`. `TimelineBlock` takes an optional `segments` prop and falls back to that demo data, so the same block can be mounted against any set of periods.

## Tech stack

- React 19 with TypeScript
- styled-components for all styling, including the `@font-face` declarations for the locally hosted PT Sans and Bebas Neue
- Swiper for the event slider
- Webpack 5 with Babel, `copy-webpack-plugin` for SVG icons and fonts, and path aliases mirrored between `webpack.config.js` and `tsconfig.json`

## Implementation notes

**Instances share nothing.** All state lives inside the component tree: the active period index in `TimelineBlock`, the dial's rotation and previous index in `TimeCircle`, the animated values in `AnimatedYears`. There is no context, no module-level mutable state, and no hardcoded DOM id — the only `getElementById` in the project is the app's root mount in `src/index.tsx`. Class names are generated by styled-components, so several blocks can coexist on one page without interfering.

**Points are positioned by trigonometry, not placed by hand.** `TimeCircle` derives the step from the data (`360 / segments.length`) and converts each index into a coordinate on the circle: `x = center + r·cos θ`, `y = center + r·sin θ`, starting at −90° so the first point sits at twelve o'clock, then shifted by half the dot's width so the dot is centred on the computed point. Any number of periods spaces itself evenly, and the radius swaps with the breakpoint. Rotation takes the shorter way around — when the index delta exceeds half the segment count it wraps in the opposite direction, so stepping from the last point to the first turns one segment instead of five. Each dot is counter-rotated by the dial's current angle so its number and label stay upright while the circle moves.

**Every period selector is wired to the panel it swaps.** The dial points, the prev/next buttons and the mobile pagination dots all call the same clamped `onSelect`, and all carry `aria-controls` pointing at the event slider — the id comes from `useId`, so two blocks on one page each resolve to their own panel. Selecting a period is otherwise a silent change for a screen reader (the slider is remounted, and a freshly inserted live region does not announce itself), so the block keeps one persistent polite live region that reads out the period name, its years and how many events it holds.

**Empty data renders, it does not throw.** Handing the block no periods used to read `date_1` off `undefined` and blank the page; it now renders the heading and "No periods to show." A period whose `sliderData` is empty used to collapse the slider to a 1px strip, so the control that led there looked broken; it now says "No events recorded for this period." Both counts are read off the data — nothing in the UI is hardcoded.

**The layout rules are part of the markup.** The vertical rules framing the content are borders on the page `Container`; the horizontal rule and the centre line are `::before` and `::after` on the block's wrapper. They are real elements subject to the same responsive rules as everything else, and they drop out below 768px along with the dial.

**Two navigation modes off one media query.** A `useMediaQuery` hook subscribes to `matchMedia` and switches between the desktop control (position counter with prev/next buttons) and the mobile one (the same counter plus pagination dots) at 768px. Swiper's own breakpoints step slides per view from 3 down to 1.5.

**Year counters clean up after themselves.** `AnimatedYears` moves each year toward its target one unit at a time on a 30 ms interval and keeps both timers in refs, so a transition interrupted mid-count clears its intervals instead of leaving two of them racing.

## Getting started

```bash
git clone https://github.com/sobol-sudo/timeline-block.git
cd timeline-block
npm install
```

Development server on port 3000:

```bash
npm run start
```

Production bundle into `dist/`:

```bash
npm run build
```

Type checking. Babel strips types without checking them, so the build alone will not catch a type error:

```bash
npm run typecheck
```

## Tests

```bash
npm test
```

Jest on jsdom with React Testing Library, transformed by the same Babel presets the bundle uses. The suites in `src/__tests__` are regression tests: each one pins behaviour that has already broken here once.

- `keyboard.test.tsx` — every control is a real button, reachable by Tab and activated by Enter or Space; the arrow at each end of the range carries a genuine `disabled` attribute and stays out of the tab order; a period list that shrinks under the current selection keeps rendering; a block with no periods offers no controls at all. The tab-order assertion is the one that matters most: `disabled` used to be a styled-components prop only, so the dimmed arrow was still tabbable and Enter on it asked for index −1.
- `clamp.test.tsx` — the block clamps whatever index a control asks for, so no selector can empty the page. The dial is swapped for a probe that requests −1 and 99; the rest of the block is real.
- `geometry.test.tsx` — points sit at equal angles for 3, 4, 6 and 7 periods, all at the same radius and starting at twelve o'clock; the dial takes the short way round rather than unwinding; the dots counter-rotate to exactly the negative of the dial's angle and on the same 0.6 s clock, so the numbers stay upright through the turn as well as at rest.
- `instances.test.tsx` — two blocks on one page get separate panel ids, every `aria-controls` resolves to an element inside its own block, no id is duplicated, and choosing a period in one block leaves the other's panel and dial exactly where they were.

Two things jsdom does not provide are supplied in `src/__tests__/helpers`: a `matchMedia` that really evaluates `max-width` queries against a width the tests set, and a reader that pulls styled-components' generated declarations back out of the injected stylesheet, because `getComputedStyle` in jsdom does not resolve class rules and the dial's rotation exists nowhere else.
